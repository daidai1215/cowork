# 协作模式手册（Collaboration Patterns）

本文件整合原 `gpt-write`（GPT 执笔）与 `gpt-review`（GPT 审稿）的全部核心规则，并适配当前固定三大主力：**GPT-6 Astra (`high`)**、**Gemini 4 Carbon (`high`)**、**Claude Opus 5.5 (`high`)**。
术语定义：**主控** = 当前对话模型（负责拍板与最终验收）；**执行者 / 审查者** = 被调用的外部模型。
所有外部调用统一通过 `scripts/invoke-model.ps1` 执行（默认全开 `high` 档），并严格遵守 SKILL.md 的“90 秒看门狗 + Cockpit 切号重连”协议。

---

## 0. 通用铁律（所有模式都适用）

1. **主控拥有最终拍板权**：主控可凭据驳回或不采纳执行者与审查者的意见。但“不采纳具体意见”不等于“跳过审查环节”，既定的预审、分块审与终审流程必须走完。
2. **拒绝防御性写作**：GPT 系模型倾向于添加冗余限定词、免责前提、“并非 X 而是 Y”套话及过度保守的表述。凡破坏语感、加重 AI 腔、拖沓篇幅的修改建议一律驳回。最终文字统一交由 `best-prose`（Gemini 4 Carbon `high`）定稿。
3. **真伪内容必须双查**（见第 5 节 Truth Gate），严禁采信单一模型（尤其 Gemini 4 Carbon 虽知识榜第 1 但幻觉率约 11%，事实数据必查）。
4. **保档位、控体积来省额度**：三个模型统一跑 `high` 档，不私自降档。Opus 靠“只审精简材料、不写长文初稿”省额度；Astra 靠“只接硬核代码/数学/生图/Office 与关键审查、不铺写普通文字”减少单号触顶与切号次数。
5. **慢模型后台异步运行**：GPT-6 Astra 响应最慢，委派任务后必须通过 `WaitMsBeforeAsync=500` 放入后台并挂载 90 秒看门狗，主控**在同一回合内继续推进其他工作**，不得空等。
6. **阶段产物落盘（防 Cockpit 切号丢上下文）**：协商方案、预审拍板结论、分块审稿意见必须实时写入 `<scratch>/*.md`。一旦 Cockpit 自动切换 Astra 账号导致旧 `<sid>` 报 `resume_invalidated=true`，立刻改用**不带 `-Resume` 的全新会话**并内联 `<scratch>` 文件无缝续接。
7. **写入隔离与验收记账**：`-Access write` 或 `extract-files.ps1 -AllowedPrefixes` 必须严格限制白名单路径；每次外部调用验收完毕，必须执行 `scripts/record-outcome.ps1 -SessionId <sid> -Outcome ok|redo|fail`。

## 1. Delegate-Execute（主控决策，执行者落地）—— 原 `gpt-write`

适用场景：将主体实现交由更擅长的模型完成（如后端、数学、Office 文档交给 GPT-6 Astra `high`；长文起草、1M 全仓梳理交给 Gemini 4 Carbon `high`），主控专注于方案决策与结果验收。

1. **方案协商（落盘）**：以只读模式（`-Access read`）调用执行者诊断现状并给出 1~2 套方案，输出保存至 `<scratch>/plan_proposal.md` 并记录 `session_id`。
2. **主控拍板（落盘）**：结合用户核心诉求与硬性指标，明确裁定改哪里、怎么改、保留什么、删除什么，写入 `<scratch>/plan_approved.md`。
3. **执行者落地**：
   - **执行者是 GPT-6 Astra（codex 通道）**：鉴于当前非交互 shell 工具限制，改用 `-Access read` 要求其按 `=====FILE: …=====` 文本块交付完整文件，由主控通过 `extract-files.ps1 -AllowedPrefixes <白名单>` 机械落盘（不篡改内容）。若 `-Resume <sid>` 因 Cockpit 切号返回 `resume_invalidated=true`，立即去掉 `-Resume`，直接把 `<scratch>/plan_approved.md` 与相关源码内联进新会话执行。
   - **执行者是 agy 通道（Carbon / Opus）**：可直接 `-Resume <sid> -Access write` 执行。
4. **主控独立验收**：核查文件修改时间、diff 与硬约束（字数、页数、测试结果）；客观事实与引用必过 Truth Gate；未达标处附具体证据打回重做，直至合格。
5. **禁止越界代劳**：在此模式下，主控除机械落盘、只读检查与实跑测试核验外，不得越俎代庖直接重写目标文件。

## 2. Pipelined Review（主控实现，审查者流水线并审）—— 原 `gpt-review`

适用场景：主控亲自执笔实现，调用另一厂商模型担任独立审稿人（全程 `-Access read`）。

1. **分块起草**：主控通读上下文，将任务拆解为若干可独立落盘的分块，并标出需按 Strength Delegation 外包的子任务。
2. **【必经】方案预审**：将需求与分块方案发给审查者挑错，记录 `<PlanSid>` 并将共识方案保存至 `<scratch>/pre_review_agreed.md`。若有异议据理反驳，不合理建议直接驳回。
3. **边写边审**：每完成一块并落盘后，立即在后台启动一个**独立的**只读审查会话（不使用 `-Resume`，既避免会话锁冲突，又天然免疫 Cockpit 切号导致的会话失效！），输出至 `-OutFile <scratch>/chunk_<n>_review.md`。挂妥看门狗后立即编写下一块。
4. **【必经】完稿汇总终审**：全稿写完且各块审查全部返回后，将各分块审查意见与最终成品交回审查者核查全局一致性与硬性指标（若未切号可 `-Resume <PlanSid>`；若审查者是 Astra 且期间发生过切号或返回 `resume_invalidated=true`，直接开新会话并附上 `<scratch>/pre_review_agreed.md`），按 `Blocker / Major / Minor` 去重分级，列出待核实的真伪线索。
5. **裁决与返工**：确属问题的由主控集中返工并复核；属主观偏好分歧或审查者误判的，凭据驳回。
6. **禁止先斩后奏**：未完成预审不得动笔；未完成汇总终审不得宣布完稿。

## 3. Aesthetic Gate（Carbon 写前端，Opus 只把关审美）

适用场景：前端页面、UI 组件、落地页、海报版式等视觉产出，以最少 Opus 额度换取最高视觉水准。

1. **起草实现**：由 `route.ps1` 选出的 primary（默认 Gemini 4 Carbon `high`）完成页面编写，抽离清晰的 design tokens（颜色、字号阶梯、间距、圆角、阴影）。
2. **多视口截图**：主控截取三个关键视口（1440 / 768 / 390）渲染画面。
3. **审美把关**：仅将截图、tokens 与关键组件片段发给 `best-aesthetic`（Claude Opus 5.5 `high`，`-Access read`），切勿发送整个代码仓。要求 Opus 输出：
   - 按“视觉层级 / 排版节奏 / 配色 / 留白 / 一致性 / 细节质感”六个维度逐项打分并指出具体问题；
   - 直接给出修改后的 tokens 与 ≤ 10 条具体 CSS 修改指令。
4. **落地与复看**：由 primary 应用修改并重新截图，交 Opus 复看一次。默认最多迭代 2 轮。
5. **Opus 不可用时的降级**：reviewer 切换为 Gemini 4 Carbon（`self_review=true`），必须另开一次独立调用对照下方清单逐项严审，不得在同一会话内自评。

**设计检查清单**：
- 层级：每屏仅保留一个视觉焦点；标题、正文、辅助文字字号比例 ≥ 1.25；
- 节奏：间距严格采用 4/8 倍数，同类元素间距一致；
- 配色：主色、强调色、中性色合计 ≤ 5 种；文字对比度 ≥ WCAG AA；
- 排版：中文行高 1.6~1.8，英文 1.4~1.6；正文每行 35~75 字符；
- 质感：圆角与阴影克制且成体系（≤ 3 档）；完整覆盖 hover / focus / active 状态；
- 去模板感：摒弃廉价紫青渐变与千篇一律的居中卡片堆砌，至少保留一处鲜明视觉记忆点。

## 4. Strength Delegation（强项子任务外包）

遇到以下独立子任务时，直接外包给对应模型的专长通道，完成后由主控验收合入：

| 子任务 | 交给（`high`） | 说明 |
|---|---|---|
| 高精度生图、科研示意图、信息图、UI Mockup、透明通道、局部重绘 | GPT-6 Astra（Codex `image_gen`） | 硬规则：生图仅走 Codex，生成后拷入项目目录 |
| PPT（`ppt-master` / `nature-paper2ppt`）、Word 修订与公式、Excel 跨表公式、可填写 PDF | GPT-6 Astra（Codex 插件） | 版式可叠加上方 Aesthetic Gate 把关 |
| 专利交底书、基金证据表的严谨逻辑骨架 | GPT-6 Astra 起草结构 | **最终成文与去 AI 腔润色必须交由 Gemini 4 Carbon 完成，严禁由 GPT 定稿** |
| LaTeX 模板编译排错、桌面/浏览器联动 | GPT-6 Astra | |
| 形式数学推导、极隐蔽并发/数值稳定性 bug、极限篇幅压缩 | GPT-6 Astra | 单次任务粒度宜聚焦，降低执行中途撞上切号的概率 |
| 整仓或超长文档（1M 上下文）通读、联网检索、世界知识综述 | Gemini 4 Carbon | 事实与文献数据须经 Astra 抽查（Truth Gate） |

## 5. Truth Gate（真伪双查）

凡涉及参考文献（DOI、标题、作者、年份、卷期、页码、核心观点）、客观统计数据、数学定理适用条件、API 签名及行为、标准编号、基准测试数值的内容，必须执行：

1. **异构模型交叉核查**：一个模型产出初稿后，交由另一厂商模型只读核查（如 Carbon 写稿 → Astra 查证引用与数据；Astra 写算法 → Carbon 独立验算），列出全部疑点。
2. **主控亲自终审**：主控必须针对每条疑点，亲自通过 `search_web`、权威学术数据库（OpenAlex / Crossref / PubMed / arXiv）或实跑脚本**逐一复核**，确保最终交付 100% 可溯源、零幻觉。
3. **严禁将真伪核验完全甩给单一模型后放弃复核。**

## 提示词模板

### A. 审查者通用模板（只读）
```
你是独立审稿人（只读，不得修改任何文件，不要调用任何 shell 工具）。
任务背景：<一句话>
待审材料：<内联内容或路径>
重点：<正确性 / 全局一致性 / 硬指标 / 真伪线索>
输出：中文，按 Blocker / Major / Minor 分级，每条写成“问题 → 证据 → 建议改法”，总长度 ≤ <N> 字。
禁止：建议增加免责声明、冗余限定词或“并非 X 而是 Y”式表述。
```

### B. 执行者通用模板
```
按以下已拍板的方案执行，不要自行扩大范围。
允许写入：<路径清单>；禁止触碰：<路径清单>。
方案：<编号列出的具体改动>
完成后汇报：改动文件清单、关键依据（文献 / 数据 / API）、存疑之处、未完成项。
```

### C. Opus 审美把关模板
```
你是资深视觉设计师，只做审美把关，不重写整页代码。
材料：<截图路径 ×3>、design tokens、关键组件片段。
请按“层级 / 节奏 / 配色 / 留白 / 一致性 / 质感”逐项给出 1~10 分和问题，
然后直接给出修改后的 tokens（JSON）和 ≤ 10 条具体 CSS 改动。总长度 ≤ 600 字。
```
